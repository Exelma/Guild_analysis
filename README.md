# Replay Lab

Локальный дашборд для разбора гильдейских матчей в *Where Winds Meet*: смотришь
запись, отмечаешь файты и события, вводишь монеты и убийства — получаешь таймлайн
матча и графики по времени.

Один HTML-файл без сборки, зависимостей и сервера: всё работает в браузере,
разметка хранится в `localStorage` и выгружается в JSON.

## Быстрый старт

1. Положи запись матча в корень проекта файлом
   `Where Winds Meet 2026 10 31 Juiced.mp4` — именно это имя указано в `<video>`
   внутри `app/index.html`. Для другого файла поправь `src` в этом теге.
2. Открой `app/index.html` в браузере: двойным кликом или перетащи файл в окно.
3. Размечай матч во вкладке **Разметка**, смотри сводку во вкладке **Графики**.

Никакой установки не требуется: браузер, локальный файл, готово.

## Как размечать

### Интервал файта

1. Перемотай к началу файта и нажми **Начать файт**.
2. Перемотай к концу и нажми **Завершить файт**.
3. Укажи, кто закончил файт в плюсе, и добавь короткий комментарий.

Интервал появится на таймлайне, а в списке отметок — его длительность и итог.

### Точечное событие

1. Встань на нужный таймкод.
2. Выбери тип (смерть, objective, экономика) и сторону с преимуществом.
3. Впиши, что произошло, и нажми **Записать на …**.

### Точки графиков

1. Перемотай к моменту, где на записи или скриншоте видно значение.
2. Выбери показатель (монеты или убийства), сторону и введи число.
3. Переключай графики стрелками или точками под ними.

Линия на графике соединяет только введённые точки. Это визуальный ориентир,
а не непрерывное измерение — промежутки между точками не считаются данными.

## Хранение и экспорт

Разметка живёт в браузере на этом компьютере. **Export JSON** сохраняет
переносимую копию, **Import JSON** возвращает её обратно. Очистка данных
браузера удалит разметку — экспорт перед этим обязателен.

## Данные

Экспорт — один JSON-объект версии 2:

```json
{
  "version": 2,
  "events":       [ { "time": 95.4, "type": "death", "side": "opponent", "note": "…" } ],
  "fights":       [ { "start": 540, "end": 605.5, "side": "opponent", "note": "…" } ],
  "metricPoints": [ { "time": 540, "metric": "coins", "side": "tenshiro", "value": 13200 } ],
  "pendingFight": null
}
```

- `time`, `start`, `end` — секунды от начала записи;
- `type` — `death`, `objective` или `economy`;
- `metric` — `coins` или `kills`;
- `side` — `tenshiro`, `opponent` или `unknown` (для событий).

Пример с заполненными полями лежит в `data/example-events.json`.

## Отчёты

`reports/катки.docx` — разбор двух проигранных файтов против REJUICED, динамика монет по таймкодам и выводы: пуш работает как ещё одна
линия обороны перед своими башнями, то есть другим отрядом, а ключевая ветка развития игроков —
агильность, то есть способность быстро реагировать на ситуацию и перемещаться по карте. Внутри три схемы с разметкой.

`reports/катки.xlsx` — сводная таблица гильдий: победы, поражения и общий
winrate. Это исходные данные для сравнения соперников.

## Что остаётся локально

В репозиторий осознанно не попадают:

- запись матча (≈740 МБ — GitHub не принимает файлы больше 100 МБ);
- 12 скриншотов матча — рабочий материал для разметки;
- личный экспорт `tenshiro-replay-analysis.json` с разметкой конкретной игры;
- пустые черновики в папке `Отчёты/` (Word и Excel сохранили файлы без содержимого).

Всё это перечислено в `.gitignore`. Если запись когда-нибудь понадобится в
репозитории, ей место в Git LFS или во внешнем хранилище, а не в обычном коммите.

## Ограничения и планы

- **Видео привязано к имени файла.** `app/index.html` ищет запись по конкретному
  имени в корне проекта. Следующий шаг — выбор файла через `<input type="file">`.
- **Нет синхронизации.** Разметка живёт в `localStorage` одного браузера, перенос
  между машинами — только через Export/Import JSON.
- **Данных пока мало.** В планах — выжившие, роли игроков, снимки экономики и
  общая база матчей вместо одного JSON на игру.

## Происхождение
